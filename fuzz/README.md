# Фаззинг

Цели [cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz) (libFuzzer) для парсеров certscan. Каталог `fuzz/` — отдельный workspace: он исключён из корневого (`exclude = ["fuzz"]` в корневом `Cargo.toml`) и в `cargo build/clippy/test --workspace` не попадает. Workspace-линты на него не действуют: нарушение инварианта в цели оформляется через `assert!`.

## Устройство

- `src/lib.rs` — тела целей и их инварианты (крейт `certscan_fuzz`). Модуль не использует `libfuzzer-sys`, поэтому собирается и тестируется на stable.
- `fuzz_targets/<цель>.rs` — обёртка `fuzz_target!`, вызывающая одноимённую функцию библиотеки.
- `seeds/<цель>/` — начальные входы из записанных фикстур, под контролем версий.
- `corpus/<цель>/` — корпус, который нарабатывает фаззер, в git не попадает.

Входы целей — «сырые» байты (поток записей либо тело сообщения) без управляющих префиксов, поэтому seed-файлы из фикстур используются как есть. Размеры порций для инкрементальных декодеров выводятся из хеша входа; `server_kx` разбирает одно тело для каждого вида key exchange и каждой версии.

## Цели

| Цель | Вход | Что проверяет |
|---|---|---|
| `record_layer` | поток TLS-записей | `Decoder`: разбор одним куском и порциями даёт одни и те же события и ошибку; каждое handshake-сообщение проходит через диспетчер, каждый alert — через `Alert::parse` |
| `server_hello` | тело ServerHello или HRR | `ServerHello::parse` и диспетчер согласованы (тот же результат, HRR распознан одинаково); расширения разобранного hello читаются без ошибок |
| `certificate` | тело Certificate (TLS до 1.2) | `CertificateList`: число элементов итератора равно `len()`, сертификаты непустые, срезы вместе с префиксами длины покрывают тело целиком |
| `server_kx` | тело ServerKeyExchange | `ServerKeyExchange::parse` для 12 видов key exchange и 6 версий: неподдерживаемые вид и версия дают `Unparsed` с телом без ошибки; `signed_params` — префикс тела; наличие подписи и алгоритма соответствует виду и версии; поля покрывают тело целиком |
| `sslv2` | ответ на SSLv2 CLIENT-HELLO | `Sslv2Decoder` одним куском и порциями; `TlsReply` и ошибка окончательны; `parse_message`, `Sslv2RecordHeader`, `Sslv2ClientHelloView`; пара «билдер — парсер» для CLIENT-HELLO |
| `server_message` | байт типа и тело handshake-сообщения | диспетчер `ServerMessage` и все типизированные методы: метод возвращает результат только для своего типа, ошибка возможна только у ServerHello и ServerHelloDone |
| `client_hello` | тело ClientHello | `ClientHelloView`; разобранный hello без расширений, собранный билдером заново, совпадает с входом побайтно; hello из полей, выведенных из входа, разбирается в те же поля, а его записи с фрагментацией декодер собирает в то же сообщение |
| `alert` | сообщение alert | `Alert::parse` принимает ровно два байта |

Инварианты инкрементальных декодеров (`record_layer`, `sslv2`, а также все места, где цель пропускает собранные записи через декодер):

- `NeedMore` возвращается, только когда поданная порция исчерпана;
- `Decoder::stream_offset()` равен числу байтов, забранных из входа;
- сумма байтов, отнесённых к событиям, не превышает числа забранных; число вызовов `feed` ограничено длиной потока — события без продвижения по входу невозможны;
- после ошибки повторный `feed` возвращает её же и вход не забирает.

Ошибка `NotTls` при разной нарезке сравнивается только по факту: в неё попадают байты, доступные в момент проверки.

План (P1-09) называет пять целей; `server_message`, `client_hello` и `alert` добавлены сверх него. Цели для X.509, HTTP-заголовков и STARTTLS-парсеров появятся вместе с парсерами, см. `docs/ARCHITECTURE.md`, раздел 9.

## Seed-файлы

Начальные входы строятся из записанных фикстур `crates/tls-probe/tests/fixtures/*.hex`:

```sh
cargo xtask fuzz-seeds
```

Команда детерминирована: удаляет прежние `*.bin` в `fuzz/seeds/<цель>/` и записывает новый набор. Её нужно повторять после записи или перезаписи фикстур; тест `seeds_on_disk_match_fixtures` в `xtask` падает, если каталог на диске расходится с фикстурами.

| Каталог | Содержимое |
|---|---|
| `seeds/record_layer/` | поток записей каждой фикстуры |
| `seeds/sslv2/` | потоки фикстур сервера (ветка «на SSLv2 hello ответили TLS-записью») |
| `seeds/server_message/` | байт типа и тело каждого handshake-сообщения сервера |
| `seeds/server_hello/` | тела ServerHello и HelloRetryRequest |
| `seeds/certificate/` | тела Certificate |
| `seeds/server_kx/` | тела ServerKeyExchange |
| `seeds/client_hello/` | тела ClientHello |

Записей SSLv2 среди seed-файлов нет: стенд на OpenSSL 4.1.0 SSLv2 не поддерживает, а синтетические байты за записанные не выдаются (`docs/PLAN.md`, P1-28). У цели `alert` seed-файлов нет: вход из двух байтов фаззер находит сам.

## Проверка без nightly

```sh
cargo check --manifest-path fuzz/Cargo.toml   # библиотека и все цели собираются
cargo test --manifest-path fuzz/Cargo.toml    # тела целей на seed-файлах
```

Тест прогоняет каждую цель на своих seed-файлах, на каждом их префиксе, на seed-файлах остальных целей и на искажённых входах. Это проверка инвариантов на известных входах, а не фаззинг: новых входов тест не порождает.

## Установка

Для самого фаззинга нужны nightly toolchain и cargo-fuzz. Основная сборка проекта остаётся на stable.

```sh
rustup toolchain install nightly
cargo install cargo-fuzz
```

Синтаксис `cargo +nightly` работает только с cargo, установленным через rustup. С cargo из Homebrew он недоступен.

## Запуск

Команды выполняются из корня репозитория. Каталог seed-файлов передаётся вторым каталогом корпуса: libFuzzer читает входы из обоих, а новые записывает только в первый (`fuzz/corpus/<цель>/`).

```sh
cargo +nightly fuzz list                                             # список целей
cargo +nightly fuzz build                                            # собрать все цели
cargo +nightly fuzz run record_layer fuzz/corpus/record_layer fuzz/seeds/record_layer
cargo +nightly fuzz run server_kx fuzz/corpus/server_kx fuzz/seeds/server_kx -- -max_total_time=600
```

Приёмка P1-09 — 10 минут на каждую цель без падений и зависаний (`-max_total_time=600`).

Воспроизвести найденное падение:

```sh
cargo +nightly fuzz run record_layer fuzz/artifacts/record_layer/<файл>
```

## Каталоги

| Каталог | Содержимое | В git |
|---|---|---|
| `fuzz/seeds/<цель>/` | начальные входы из фикстур, создаёт `cargo xtask fuzz-seeds` | да |
| `fuzz/corpus/<цель>/` | локальный корпус входов, пополняется при запуске | нет |
| `fuzz/artifacts/<цель>/` | входы, вызвавшие падение, таймаут или OOM | нет |
| `fuzz/coverage/<цель>/` | данные `cargo fuzz coverage` | нет |
| `fuzz/target/` | сборка | нет |

Четыре последних каталога перечислены в `.gitignore`. Вход, воспроизводящий исправленную ошибку, переносится в фикстуры соответствующего крейта как регрессионный тест (формат — в [tests/fixtures/README.md](../tests/fixtures/README.md)).
